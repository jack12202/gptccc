# 后台首页日常工作台

2026-10-12：首页实现完成。原 /admin 地址直接显示工作台，保留统一会话及原有完整管理页面。

- 顶部展示在用支付卡、可用卡、当前 Plus 通道可轮选次数、冻结次数、未使用客户卡密和待处理订单，点击统计可定位筛选。
- 支付卡区只显示未停用卡；暂停、次数耗尽、冻结等需处理卡保留。可直接录卡、同步、加次数、解冻、批量调整，管理详情在同页弹窗打开。
- 最近订单默认每页 10 笔，搜索及待处理查询覆盖全量记录。原始 JSON、客户卡密、UUID 可按需复制；Plus 与 Pro 分别使用已有处理接口。同页订单弹窗可核查、记录备注、分配人工卡、确认结果，返回日志默认折叠且按需读取。
- 最近客户卡密默认每页 20 张，同页生成、复制、下载 TXT ZIP、批量查卡、按批次复制导出，以及启用、禁用、归档。状态标签数量跟随搜索和批次条件；顶部未使用数量覆盖全部未归档卡密。失败且未解锁的卡密标为待确认，绑定信息来自最新关联订单。
- API、通道、Pro 配置放在折叠设置区。首页加载只读本地记录，不自动查询上游、切换协议、生成卡密或提交充值。输入、弹窗和操作期间暂停自动刷新，返回的旧请求不能覆盖较新的筛选结果。

实现：src/admin-workbench.js 负责统一卡片可用性及范围筛选，GET /api/admin/workbench 返回首页快照。最近窗口限制只影响传给浏览器的记录数，较早的待处理记录仍可搜索处理。JS 资产沿用部署已有的 /admin/cards/ 反代范围，并受统一后台会话保护；不新增公共静态业务数据。

验证：完整 97 项测试，包括新增的停用/暂停/耗尽/占用卡口径、当前通道可轮选次数、全量搜索与待处理、批次计数、卡密与订单状态、北京时间日期筛选、受保护资产和有界首页快照。浏览器使用隔离数据库与虚构资料验证录入卡、预览、增加次数、解冻、生成批次、复制、TXT ZIP 导出、订单 JSON 复制、Pro 备注与同页弹窗。导出的 ZIP 通过 CRC、条数及充值链接格式校验。购买链接锁与站点检查通过。

发布验证：scripts/verify-admin-session.mjs 在现有生产部署流程中使用自己的临时会话，只读检查首页区块、脚本资产和快照，并撤销该验证会话。该流程不调整真实卡的次数、不解锁真实订单、不发起充值、不修改 provider 或 API 配置。实际发布结果以 GitHub Actions 对应提交的成功记录为准。
