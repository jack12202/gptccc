# 卡池直接增加次数与解锁冻结

2026-10-12：本地实现与验证完成，尚未推送或部署到生产。

支付卡池每行提供「＋1 次」「增加…」及有冻结时的「解锁冻结」。增加次数不要求修改备注；总次数与剩余次数同时增加，已消耗、已冻结、启停及暂停状态保持原值。嗨付和 ZZS 使用同一份次数记录。顶部「可用」和「冻结次数」直接展开、筛选并定位列表。

订单列表中的 ZZS 失败和待确认冻结记录直接显示「解锁冻结」，无需展开详情。解冻时核实未扣款：失败订单只释放对应支付卡次数；待确认订单沿用原有人工解锁流程，原订单结为失败，原卡密可为原账号重试。原订单历史保留。旧失败订单解冻不会解锁该卡密的新提交。

新增 POST /api/admin/zzshu/cards/:id/add-uses，参数 amount 为增加量、requestId 为客户端请求标识。使用 SQLite 事务按数据库最新总次数增量更新；card_usage_adjustments 持久化去重，防止同一请求重试或重启后重复加次数。继续要求后台会话、来源校验和 CSRF。总次数上限沿用 100。冻结次数按关联订单逐笔处理，同一笔只能释放一次。

验证：仓库根运行 node --test recharge-center/test/*.test.js，94 项全部通过；购买链接锁检查、站点配置检查和 git diff --check 通过。本地浏览器使用独立临时数据库与虚构支付卡验证了快捷筛选、一键加 1、输入增加 2、待确认订单解冻以及卡池统计同步，并检查桌面和窄屏布局。未读取或修改生产业务数据，未发起真实充值。
